# AirSight — Interactive Airport Operations Outlook

AirSight is a decision-support dashboard for exploring the **next three hours of airport traffic forecasts** at King Khalid International Airport (RUH).

The Streamlit interface uses the final output of the AirSight integration pipeline:

**Residual LSTM → 3-hour traffic forecast → Operational Pressure → Historical Context → Readiness Recommendation → Interactive Dashboard**

## What the dashboard does

The user selects any available forecast start time from the held-out test period. The dashboard then updates the complete three-hour outlook:

- `t+1`, `t+2`, and `t+3` forecasted movements
- `Normal`, `High`, or `Extreme` operational pressure
- pressure-aware card and status colors
- comparison with historically typical traffic for the same hour/day
- readiness recommendations from the integration pipeline
- a dynamic three-hour Operational Outlook summary
- Traffic Context and Operational Pressure Level panels

The dashboard does **not** make direct operational decisions such as flight delays, cancellations, gate assignments, or staffing decisions. Its recommendations are readiness-oriented decision support.

### Folder responsibilities

- `app.py` — Streamlit entry point and page orchestration.
- `src/components.py` — reusable dashboard UI components.
- `src/dashboard_logic.py` — presentation logic for the selected 3-hour forecast window.
- `src/data_loader.py` — data loading and validation.
- `assets/styles.css` — dashboard styling only.
- `data/` — input consumed directly by the Streamlit app.
- `results/` — evaluation outputs kept for reporting/documentation.
- `.streamlit/config.toml` — Streamlit application configuration.

## Data contract

`data/airsight_dashboard_data.csv` is produced by `AirSight_Final_Integration_v2.ipynb`.

Required columns:

- `forecast_origin_local`
- `target_hour_local`
- `horizon`
- `forecast_movements`
- `predicted_pressure`
- `expected_traffic`
- `forecast_vs_expected`
- `traffic_zscore`
- `traffic_context`
- `recommendation`

Each forecast origin must contain exactly three rows: `t+1`, `t+2`, and `t+3`.

All dashboard-facing timestamps are in **KSA time (UTC+3)**.

## Run locally

From the project root folder (the folder that contains `app.py`):

```bash
pip install -r requirements.txt
streamlit run app.py
```

If `streamlit` is not recognized on Windows, use:

```bash
python -m streamlit run app.py
```

## Design

The interface follows the team Figma prototype `AirSight / updated-2` in `try_Airsight_v2`, keeping the single-page Overview structure:

- AirSight branding and Overview sidebar
- forecast start-time selector
- three forecast cards
- Operational Outlook
- Traffic Context
- Operational Pressure Levels

## Implementation notes

The Streamlit application intentionally consumes the **dashboard-ready test-set output** rather than retraining or rerunning the Residual LSTM inside the UI. This keeps the dashboard aligned with the evaluated integration notebook and avoids duplicating model logic in the presentation layer.

`src/data_loader.py` validates the input schema and requires every forecast origin to have all three horizons before the app renders.

`src/dashboard_logic.py` contains only dashboard presentation logic. The readiness recommendations shown in the cards are read directly from the integration output and are not regenerated by Streamlit.
